# Axiom Studio V0.4：从软件开发流程到可核验的软件生产协议

**定位基线不变**：Axiom Studio 不重复制造已有的软件开发工具；利用 VS Code 等第三方基础设施，将需求与规格、AI 构造、独立验证、可信证据、质量决策和持续演化组成完整软件工程体系。

## 为什么不是再做一个代码生成器

代码生成只是生产过程中的一个阶段。若需求不被固定、候选与证据不可追溯、旧验证被错误复用，AI 产生更多代码反而提高治理难度。因此 V0.4 将**生产过程本身**作为可记录、可判定、可失效的软件对象。

## 本版实现的生产对象

| 对象 | 可追溯的约束 | 工程含义 |
|---|---|---|
| Intent/Requirement | `REQ-*`、自然语言陈述、验证类型 | 明确构造意图，尚不等于形式证明 |
| Axiom Property | 规格 IR 中真实存在的性质、表达式指纹 | 人工将需求绑定到可检查性质 |
| Production Contract | 固定规格/清单哈希、需求映射、Gate 策略 | 一次构造周期的不可变约束快照 |
| Construction Packet | 需求、动作、性质、保护范围、独立验证步骤 | 可交给外部 AI 的受约束任务，不直接执行 |
| Evidence / Decision | 原模型证据、候选 C++ 检查、人工原型裁决 | 与原 Axiom 验证工具和 V0.3 编排状态机连接 |
| Prototype Passport | 当前契约、候选、验证链、审计链头及实时 Gate | 测试级快照，不是发布批准或密码学签名 |
| Evolution Branch | 新工程版本需新建契约 | 修改后不继承原有批准 |

## 从想法到可信原型的生产流程

```text
Requirement → Human-confirmed mapping → Immutable contract
                                               ↓
                                        AI task packet
                                               ↓
                                   Candidate staging & review
                                               ↓
                          Apply approved hash → independent checks
                                               ↓
                          Evidence Gate → human test-only decision
                                               ↓
                         Live gate replay → prototype passport
                                               ↓
                         Evolution: new contract & re-verification
```

**关键阻断条件**：契约缺失；规格或清单变更；需求没有真实 Axiom Property；人工审查不在当前版本；验证链缺项；C++ Gate 失败；事件链本地完整性校验失败。流程不会把 `model-bounded` 推导为通用实现正确，也不会将 `cpp-tested-prototype` 推导为生产可发布。

## 当前能力的边界

1. 需求—性质映射当前检查**标识存在和性质表达式哈希**。无法自动证明自然语言需求和公式语义等价；这需要人工审查与独立方法。
2. 性质检查属于有限抽象模型的 `Bounded`；C++ 检查是有限测试与工具辅助分析，不是通用精化证明。
3. 审计链和生产护照仅采用本地 SHA-256 内容寻址，不具备外部可信签名与独立时戳；有权限重写 SQLite 的攻击者仍可伪造全链。
4. 生产护照是在签发时重新调用当前实现 Gate 的**测试级记录**。查询历史只检查局部摘要与版本状态，不代表重新执行 Gate。
5. C++ 候选默认禁止不经人工批准的运行，当前隔离并非生产级恶意源码沙箱。
6. 无自动执行的多 Agent 软件工厂。外部 AI 候选生成、审批、独立验证仍遵循 V0.2/V0.3 的显式流程。

## 新增 API（本地 token 鉴权）

- `GET /api/production/draft?id=<workflow-id>`：解析 Axiom 规格，建议需求映射，不写入契约。
- `POST /api/production/freeze`：提交 `id/requirements/baseline`，冻结一次性生产契约，事件链记录摘要。
- `GET /api/production/status?id=...`：当前需求覆盖与 Gate 阻断原因。
- `GET /api/production/graph?id=...`：结构化需求—属性—候选—证据—决策关系。
- `GET /api/production/task?id=...`：带 SHA-256 的外部 AI 构造任务包。
- `POST /api/production/passport`：显式 `confirmation=issue_test_only`、契约摘要、独立证据与实时 Gate 均通过后签发。
- `GET /api/production/passports?id=...`：历史测试级护照，注明未重新运行 Gate。

## 运行和复现

```bash
python -m pip install -r requirements.txt
python run_studio.py --no-browser
python -m pytest -q studio/tests/test_production.py studio/tests/test_production_http.py
python scripts/production_demo.py --output reports/V04_production_demo.json
```

实验报告中 `blocked_without_cpp_evidence=true` 是有意设计的安全结果：**模型通过仍无法直接签发实现级护照**。
