# Axiom Studio V0.8 · 可持续使用的生产任务运行器

## 产品定位

遵守 Axiom Studio 已冻结的产品定位：统一 AI、行为规格、程序构造、独立验证、可信证据和可信演化；代码查看和调试继续使用 VS Code，不自建编辑器。

本轮实际交付 **模型级批量生产任务运行器**：把多个独立项目尚未完成的规格验证聚合为一批，后台执行，通过后推进原有生产流程。此版本**没有**自动生成 C++、自动批准发布、通用多 Agent 编程，也未实现不可信代码的安全沙箱。

## 使用

浏览器：软件构造全景 → 生产任务中心 → **批量执行安全规格验证**。确认后执行，自动轮询批次结果。只有 `draft` 可自动入批；失败重试必须点击 **显式重试失败项**，且重新产生不可覆盖的批次记录。规格或工程清单发生变化，旧批次阻断。

命令行：

```bash
python scripts/production_cli.py init --template model-toggle --slug example-a --name 'Example A' --goal '验证开关状态规格'
python scripts/production_cli.py init --template model-ledger --slug example-b --name 'Example B' --goal '验证两账户守恒'
python scripts/production_cli.py batch-model
python scripts/production_cli.py runs
python scripts/production_cli.py run-report batch-XXXXXXXXXXXXXXXX
python scripts/production_cli.py export-run batch-XXXXXXXXXXXXXXXX --output handoff.zip
python scripts/production_cli.py retry-run batch-XXXXXXXXXXXXXXXX
```

`batch-model` 默认只执行尚未验证的模型，限定最多 20 个工程。单项目检查调用**既有独立引擎**完成 `check → plan → verify → gate --target model`，每阶段通过才继续。底层有限状态结论为 `Bounded`，不是全程序形式证明。任何 C++ 编译运行仍须通过原有单独授权的工作流。

## 安全约束

1. 创建批次只是规划，无自动运行；执行需要显式动作。
2. SQLite 持久化批次/项目状态；运行前核对项目当前规格与工程清单摘要；漂移即标为 `stale`。
3. 模型违例、超时和验证异常均不得晋级为 `passed`；结果保留诊断。
4. 重启后将未完批次标记为 `interrupted`；对于处在 `checking` 的项目，记录 `Unknown` 并阻断，不把未完成工作当作证据。手动重试会创建新批次，保留旧历史。
5. 导出批次包含报告和**通过模型检查项目**的独立交接包，不导出证据 SQLite、API Key、授权私钥。全部文件带 SHA-256 清单；交接包**未签名**，接收方应独立复验。
6. 不支持生产发布授权，UI 中的项目/批次 `passed` 只意味着模型级 Gate 通过；需求确认、C++ 验证及人工裁决依旧独立进行。

## 当前工程边界与下阶段

本地研究原型适用于单个受信任的本地 Studio 服务实例；尚无分布式租约、云端工作池、多租户隔离、生产级隔离执行或受硬件保护的独立证据签署。批次运行仍顺序执行（不是多个 AI/编译进程并行）。大规模工程需要进一步实现任务租约、资源配额、失败诊断驱动的受限候选修复、分布式 Agent 适配、可信密钥体系与真实工程基准测试。
