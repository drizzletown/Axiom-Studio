# Axiom Studio V0.9｜AI 构造生产工单与诊断反馈

## 设计基线

产品定位保持冻结：Axiom Studio 是面向 AI 的软件构造与可信演化体系，而非新代码编辑器。VS Code 承担编辑和调试，Axiom Studio 负责行为规格、构造、独立验证、证据、裁决及演化组织。

V0.9 在 V0.8 的批量模型验证与 V0.2 的候选审查上，新增可持久化的 AI 工作订单 `studio/workorders.py`，将**受限的一个 C++ 实现文件**的候选/验证/修复过程组织为显式状态机。不是多 Agent 并行平台，不拥有未经授权的自动生产发布权。

## 可操作的实际生产循环

1. `create`：选择 C++ 工程清单、非测试实现目标及自然语言目标；冻结 Axiom 规格、目标源码、全部工程清单文件的 SHA-256。
2. `generate` 或 `submit`：经同意调用已配置的 OpenAI-compatible chat completions 接口，或粘贴由 VS Code/其他 AI 完成的候选。模型返回只暂存对象，不写工作区。
3. `review`：人工检查完整候选并确认 SHA-256；独立检查规格/测试/头文件未变化。
4. `apply`：人工明确授权替换实现，先产生可校验备份。
5. `verify`：经过**第二次明确授权可信本地 C++ 执行**后，复用原 Axiom 引擎的规格检查、模型 Gate、C++ 全量测试和实现 Gate。工作订单本身不自行出具“已通过”结果。
6. `poll`：当真实验证任务返回，检查候选状态、结果和摘要；任何失败、超时、重启丢失或证据不匹配均不允许变成 `passed`。
7. `feedback` → `revert` → `generate`：导出实际错误诊断，人工确认回退后发起下一轮 AI 候选；模型提示仍禁止更改规格、测试、Gate。单工单最多 3 轮，以避免无界自主修改。

支持顺序：`ready → proposed → reviewed → applied → validating → passed | blocked → reverted → proposed`，另有 `interrupted`。工单 JSON 原子保存，带事件哈希链。哈希链仅提供普通意外篡改检测，**不抵御具有本机文件系统写入权的攻击者**，也不构成独立证据签名。

## 运行

```bash
python -m pip install -r requirements.txt
python run_studio.py
```

进入**软件构造全景 → AI 软件生产工单**。生成前需在本机设置 `AXIOM_STUDIO_LLM_ENDPOINT`（HTTPS 或 loopback HTTP）、`AXIOM_STUDIO_LLM_MODEL`，可选 `AXIOM_STUDIO_LLM_API_KEY`；密钥不写入工单或导出包。无模型账号也可使用“粘贴外部候选”完成循环。

命令行：

```bash
python scripts/workorder_cli.py create --manifest cpp_project/project.json --target cpp_project/ledger.cpp --goal '实现安全的账户转账'
python scripts/workorder_cli.py list
python scripts/workorder_cli.py get wo-<ID>
python scripts/workorder_cli.py generate wo-<ID> --confirm
python scripts/workorder_cli.py submit-file wo-<ID> --file /path/to/candidate.cpp
python scripts/workorder_cli.py review wo-<ID> --digest <SHA256>
python scripts/workorder_cli.py apply wo-<ID>
python scripts/workorder_cli.py verify wo-<ID> --confirm
python scripts/workorder_cli.py poll wo-<ID>
python scripts/workorder_cli.py feedback wo-<ID>
python scripts/workorder_cli.py revert wo-<ID>
```

`verify --confirm` 是**本地原型授权**；切勿用于未经审查的恶意或高风险代码。已有 P1/P2 实验性隔离不等于完整容器沙箱。

## 验收证据与边界

- V0.9 专项自动化测试：`PYTHONPATH=studio:engine/src python -m pytest -q studio/tests/test_workorders.py`，8/8 通过。
- 独立真实 C++ 正确候选：`python scripts/v09_real_verify.py`，`passed`，约 21.66 秒（一次实测）。
- 独立真实 C++ 故障候选：`python scripts/v09_real_verify.py --bad`，`blocked`，约 16.23 秒（一次实测）。
- 模拟 OpenAI-compatible 本地服务器确实收到了授权需求、规格和源码并返回候选。**未验证任意真实远程模型生成质量**。
- Node 检查前端脚本语法通过。
- V0.9 与部分历史测试合并执行时再次超时；**不主张完整历史回归通过**。具体测试日志和已知问题随包提供。
- 准入仅为 `cpp-tested-prototype`。不等价于形式化精化证明、所有调度穷举或生产发布许可；模型检查保证范围仍受有限状态模型约束。

## 下一阶段的可量化生产力目标

将工作订单与 V0.8 批次任务图进一步关联，支持多文件原子修复、端到端吞吐/失败恢复的稳定运行，并以真实项目按任务成本衡量交付效率。完成受保护的独立执行沙箱与证据签署前，不应允许无人值守执行未经审查的 AI C++ 程序。
