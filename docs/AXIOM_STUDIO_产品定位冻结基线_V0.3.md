# Axiom Studio IDE 产品定位冻结基线（V0.3）

**冻结声明：** Axiom Studio 不重复制造已有的软件开发工具，而是把 AI、程序构造、行为规格、独立验证、可信证据与持续演化组织为一个完整的软件工程体系。

## 产品定位

Axiom Studio 是面向 AI 的软件构造与可信演化体系。它的主要对象是软件构造过程，不是文本编辑行为。其核心职能包括：

1. 从需求和开发意图导出可审查的行为规格、边界与验证义务；
2. 组织 AI 或传统工具提出实现候选，保留不同候选和实施依据；
3. 将候选置于独立验证体系下，保留真实检查结果与反例；
4. 根据可信证据和受保护的策略执行质量 Gate 与人工裁决；
5. 对规格、实现和依赖的变更进行影响分析、证据失效管理与重新验证；
6. 以项目全景展示需求、构造任务、候选、验证、证据、决策和演化历史的关系。

## 工具复用原则

语言编辑、语法高亮、LSP、调试器、Git、CMake、测试运行器与 AI 模型均应优先复用现有成熟工具。VS Code 是编辑/调试适配器，不是 Axiom Studio 的语义内核。Axiom Core、流程编排器和证据机制应能够脱离 VS Code 独立使用。

## 受保护的不变量

- Axiom 0.2 理论基线保持冻结，不以新 IDE 功能改变规格语义。
- AI 不得自行更改受保护规格、测试、独立验证工具或质量准入政策。
- 原始候选、人工审查、应用源码、可信执行授权、独立验证和最终裁决是不同操作。
- 证据必须标明具体工件、版本、工具与验证范围；修改依赖会使旧结论失效。
- `Bounded` 与 `Tested` 是有限/受限验证结论；即使原型 Gate `Approved`，也不意味着生产发布许可。
- 默认不得把不可信 AI 代码交给实验性的本地 C++ 执行器。

## V0.3 本次交付边界

完成统一项目对象、持久状态转换、真实规格检查/模型 Gate、既有候选系统衔接、受保护的人工测试级准入、演化分支、事件摘要链审计与项目仪表盘。VS Code 使用原生 `.code-workspace` 和任务接入，不再开发新的编辑器能力。未完成企业权限、分布式签名、生产级沙箱、自动模型迭代、跨平台远程构建、形式化 C++ 证明。所有 API 为仅限 loopback 的本地原型。
