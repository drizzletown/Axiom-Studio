# Axiom Studio V0.5：受约束 AI 软件生产编排引擎

## 冻结产品定位

Axiom Studio 不重复制造已有的软件开发工具，而是把 AI、程序构造、行为规格、独立验证、可信证据与持续演化组织为一个完整的软件工程体系。代码编辑、Git 和调试使用 VS Code 或第三方工具，不作为 Axiom Studio 的核心竞争力。

## V0.5 实现范围

本版新增 `studio/factory.py`，以冻结的 V0.4 生产契约为输入，形成可持久恢复的单目标软件构造活动（campaign）。将行为规格检查、候选生成/提交、人工代码审查、人工批准应用、受授权的独立 C++ 验证、人工 Gate 裁决组织为受控状态机。状态保存在 SQLite；每次成功的业务状态变更写入 SHA-256 本地哈希串接事件日志。

### 构造任务 DAG

`spec → construct → review → apply → verify → decision`

其含义分别为：有限规格检查、模型或人工候选暂存、人工审查 SHA-256、人工授权应用、独立 Axiom 检查与 C++ Gate、人工确认**仅供原型测试**的准入。代码构造工具不能提升自己的验证权限；验证失败、运行进程丢失、构造契约过期均不得被自动改写为通过。

### 用户可调用接口

- `POST /api/factory/create`：绑定冻结契约、规格、目标、项目清单和构造任务摘要；同一活动重复调用返回同一个 ID；活动未完成时禁止另开同项目不同目标。
- `POST /api/factory/verify-spec`：用原 Axiom 模型引擎验证规格及 Gate。
- `POST /api/factory/candidate`：手动提交完整候选源码，或用户确认后使用已配置模型；任何候选仅暂存。
- `POST /api/factory/review`、`POST /api/factory/apply`：人工 SHA-256 审查、分离的应用授权。
- `POST /api/factory/validate`：人工确认可信本地代码后，异步调用原 Axiom C++ 四步独立验证链。
- `GET /api/factory/poll`：获取验证任务最终结果；服务器重启导致任务状态丢失时阻断。
- `POST /api/factory/decide`：再次核验原引擎 Gate 并限制为 prototype-only 人工裁决。
- `GET /api/factory/events`、`GET /api/factory/repair`：本地操作审计、失败诊断及新演化分支的受约束修复任务。

所有接口继承本机令牌认证。HTTP API **不是多用户身份和角色控制系统**；人工确认表示使用本地令牌的操作者明确授权，尚未提供正式身份鉴别、独立签署或密钥保护。

### 生产原则

1. 冻结契约、行为规格、测试、Gate 策略不允许 AI 候选擅自修改。
2. AI 无权自行批准候选、应用代码、执行未经审查的 C++ 或签发生产发布。
3. 独立验证在用户授信的本地工作区运行，尚不适合执行恶意或不可信代码。
4. 单次活动一次仅处理一个明确的 C++ 目标，不宣称已支持任意复杂项目的多 Agent 自动规划。
5. 验证失败提供诊断与修复任务包，但修复须新建演化分支、重新冻结契约；**不自动降级验收标准**。
6. 本地哈希审计不能抵御具有磁盘写权限的恶意修改；须进一步引入独立签名/不可变存储。

## 运行与重现

```bash
python -m pip install -r requirements.txt
python run_studio.py

# V0.5 独立生产演示，含真实 C++ 编译测试和 Gate
PYTHONPATH=studio:engine/src python scripts/factory_demo.py --timeout 85

# V0.5 专项验收
PYTHONPATH=studio:engine/src python -m pytest -q studio/tests/test_factory.py studio/tests/test_factory_http.py
```

Windows 使用 `启动AxiomStudio.bat`；Linux / WSL2 建议运行真实 C++ 验证，取决于本机编译器与已安装依赖。

## 尚未实现 / 不应误读

- 目前可选调用外部 AI 模型，尚未实现跨 Agent 任务规划、无人值守自动修复、无限多轮迭代或自动生产发布。
- 规格模型验证依然是有界结论；C++ 端为范围明确的测试证据，不等价于通用形式化精化证明。
- 长期版本演化策略与多任务并行调度仍需增强；一次运行最多负责一个实际源码修改目标。
- 历史引擎全量测试存在旧版超时，独立 V0.5 端到端通过不代表所有历史测试全绿。
