# Axiom Studio 1.2.0：行为验收场景与规格缺口工作台

2026-10-28 · 本地源码发行版 · 基于 1.1.0 增量开发

## 核心价值

用户不用先学 Axiom 语法：在首页说出软件目标，选择示例起点并进行真实的有限模型验证，然后点击「确认验收标准」。新版引导用户为每一项验收行为回答四个直观问题：行为叫什么、在什么情况下、发生什么动作、必须得到什么结果。用户可以添加新的例外或业务行为，并明确关联现有 Axiom Property，或者诚实地标记为“暂无对应规则”。

**这意味着**：项目意图先被拆成可讨论和可审查的场景，未覆盖的需求缺口不再隐没在形式规则的通过状态中。用户可一键生成带规格原文、现有场景、缺口、摘要与禁止修改项的 AI 规格设计任务，复制给 AI 或 VS Code 辅助设计新规格。候选规格需要人工审查、创建演化版本并重新验证。

## 交付功能

- 本地 SQLite 持久化验收场景草稿；`version` 乐观并发检查，SHA-256 摘要核验。
- 场景字段和规格 Property 服务端逐项校验；虚假的性质名称不允许提交。
- 场景覆盖情况说明：已关联/未关联仅代表可追溯映射，不是需求语义蕴含或形式证明。
- 未映射场景冻结时保留为 `unverified`，被既有生产准入机制阻断。
- 在独立规格验证通过、当前基线一致、审计链正常、草稿摘要匹配、用户明确批准后才能冻结生产契约。
- 冻结契约中的 `human_review_source` 记录场景草稿摘要；修改已经冻结的需求必须进入新演化分支。
- 新增经令牌授权的 `/api/intent/plan`、`/api/intent/task`、`/api/intent/save`、`/api/intent/confirm`。
- 既有 Studio、Axiom 引擎、VSC 工作区与 AI 候选流程均保留。

## 使用步骤（不要求写代码）

1. 双击 Windows 的 `首次安装并启动AxiomStudio.bat` 或运行 `python run_studio.py`。
2. 在「你希望软件完成什么？」填写目标并建立项目。
3. 运行「检查行为规则」（有限模型检查，不执行 C++）。
4. 点击「确认验收标准」，阅读/编辑“前提 → 动作 → 结果”场景，按需添加业务行为。
5. 如果有“暂无对应规则”，点击「生成给 AI 的规格设计任务」。这是人工审阅的设计输入，不会自动修改工程。
6. 完成逐项审查并确认冻结；未映射需求仍阻断软件准入，必须在新演化分支解决。

## 安全和可信边界

1. 自然语言目标或 Given/When/Then 场景不会自动成为形式化规格。
2. Property 关联只是人工追溯映射，不是业务需求的语义证明。
3. 有限模型的检查只覆盖当前模型、状态空间和工具报告的范围。
4. 系统不自动运行生成的 C++，不替 AI 签发生产发布许可，不自动降低 Gate 标准。
5. 本地单用户工作台、事件摘要与 SQLite 完整性检查不构成生产级安全隔离或独立数字签署。
6. 旧版联合回归偶发超时仍是已知问题，不能据新增专项通过推断全量无故障。
