# Axiom Studio 1.8：并行准备，受控集成

## 新范式与使用路径

用户负责软件意图、验收规则及关键取舍；AI / VS Code 负责提出模块实现；Studio 负责拆解、准备、候选暂存、人工审查、独立验证、证据及演化。**此版本的并行仅限只读构造任务准备，绝不并行修改共享项目，也不会自动执行 C++。**

1. 在首页描述目标，创建 C++ 工程，运行独立模型验证，人工确认并冻结验收规则。
2. 在「跨模块软件生产计划」选择项目，创建任务图。专业用户可用 `scripts/task_graph_cli.py create <项目ID> --tasks-json tasks.json` 定义无环依赖；默认任务为串行依赖。
3. 点击「并行生成各模块构造任务」。系统使用最多 4 个工作线程只读读取规格、测试名称及原源码，并生成与契约摘要绑定的任务包。前置依赖尚未完成的任务也可以**准备**，但不可执行或准入。
4. 将每个模块的任务包交给 AI / VS Code，或人工编写实现；将完整单文件 C++ 候选粘贴到模块下方，点击「只暂存候选」。暂存文件保存在内容寻址对象库，绝不修改工作区。
5. 当前置模块通过真实独立测试后，点击「提交人工审查」。如果别的模块已经被验证并发生变化，Studio 要求人工复核接口兼容性。只有输入和候选摘要仍有效时才能进入原有生产线。
6. 原有生产线要求人工审阅候选摘要、单独授权应用、再单独授权实际 C++ 编译与测试。失败时诊断只能供修订用，不能修改受保护测试、规格或 Gate。
7. 生产任务可导出带哈希的本地交接记录；哈希不是外部可信签名；测试通过并不自动取得生产发布批准。

## API 与命令行

- `POST /api/fleet/prepare` JSON `{ "id": "tg-...", "parallelism": 3 }`：只读准备、幂等。
- `GET /api/fleet/get?id=...`：任务包、候选摘要、依赖状态。
- `POST /api/fleet/stage`：提交 `id,target,code,packet_digest`；校验后暂存，不执行。
- `POST /api/fleet/promote`：提交 `id,target,candidate_sha256,acknowledge_rebase`；进入人工审查，**绝不自动批准**。
- `POST /api/fleet/feedback`：独立验证失败后才允许生成修复任务，诊断仅作为非可信数据。
- `GET /api/fleet/handoff?id=...`：导出未签名、测试级交接对象。

CLI：`python scripts/fleet_cli.py --help`。所有 HTTP 调用使用原有本地会话令牌；默认只监听回环接口。执行生成的原生代码需要单独人工授权；尚不具备生产级恶意代码沙箱或第三方签署。未配置真实 AI 时仍可复制任务包，并通过 VS Code 导入候选。

## 可核查边界

- 并发**任务包准备**：已实现；并发模型调用、AI 自动合并、无人值守执行：未实现。
- 冲突处理：乐观哈希检查、依赖门禁、明确重基确认；不同模块验证仍串行。
- 验证：复用原有模型检查、C++ 项目测试及 Gate。用户自然语言目标与规格之间的关系依旧需人工确认。
- 可靠性：受保护文件漂移、任务记录篡改、候选对象篡改、错误摘要、未到达依赖阶段均以阻断处理；本地哈希链不能抵御同时掌控数据与签名密钥的攻击者。
