# Axiom Studio 1.1.0 — 意图优先与零培训软件生产体验

## 产品目标

第一次使用的人不应先理解 Gate、Property、Trace、IR 或文件清单，而应直接回答三个问题：**软件叫什么、想完成什么、从哪个可验证起点开始**。系统展示每个项目的当前证据、阻断原因和唯一主要下一步。完整专业工作流仍在折叠区供进阶使用。

## 本版实现

1. **意图优先首页**：自然语言目标、项目名称、三个清楚的项目起点；无需手动命名路径、读取 JSON、写代码。
2. **五步可解释范式**：说出目标、明确规则、生成方案、独立验证、决定与演化。每一步说明责任人、产出和限制。
3. **下一步引导**：将真实服务状态转换成可理解的任务，如检查行为规则、确认验收标准、获取 AI 开发任务和建立新版本。
4. **人工验收向导**：逐项显示当前规格性质和对应需求解释，审核并勾选后调用原生产契约冻结接口。
5. **专业功能按需展开**：多文件事务、批量任务、候选工作台、证据与高级编辑仍可访问，但不再抢占默认流程。
6. **结构化应用接口**：`GET /api/journey`、`POST /api/journey/start`，从既有模型 Gate、契约、审计状态计算，不发明验证结论。

## 不会做的事

- 自然语言目标不会自动被翻译成可证明的 Axiom 规格。项目模板只是演示起点。要把业务目标纳入形式化验收范围，仍须审查和完善规格。
- 新建项目不会调用远程模型、编译或运行 C++，不会触发 Gate 审批。验收契约必须逐项人工确认。
- 测试级 Gate 不等于生产发布授权。本地执行原生代码的隔离仍非生产级。
- 不重复建造代码编辑器，保留 VS Code 集成。

## 验收覆盖

新增 8 项专项测试覆盖初始状态、真实目标创建与隔离、无自动执行、真实模型验证、契约状态、文件变化保守失效、审计错误默认阻断和 HTTP 鉴权；另外以本地浏览器桥接完成从创建到人工契约冻结的交互冒烟。独立 Chrome 直接访问 loopback 在该执行环境被管理员策略阻断，浏览器冒烟使用页面脚本与同一真实后端的本地桥接，不将其宣称为原生浏览器本机网络验收。

## 使用步骤

Windows 双击 `首次安装并启动AxiomStudio.bat`；跨平台使用：

```bash
python -m pip install -r requirements.txt
python scripts/release_selftest.py
python run_studio.py
```

首页填写目标和名称，推荐先选「开关状态」。点击「建立我的软件构造项目」，再点「检查行为规则」。通过后点击「确认验收标准」，逐项审阅并确认。真实实现候选请继续在项目专业工作流或 VS Code 完成。
