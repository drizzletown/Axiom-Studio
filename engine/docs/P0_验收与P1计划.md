# AX-IMP-P0-0.1：P0 实施说明、验收与 P1 计划

日期：2026-10-25 | 设计依据：AX-HLD-1.0 | 冻结理论：AX-BL-0.2

## A. 本轮执行顺序

1. 校核 AX-HLD-1.0（14 章）与 AX-BL-0.2：保留五原语、一套行为语义和模型—绑定—实现保证分层。
2. 定义最小 `.ax` 文法，并实现表达式 AST、类型检查、状态和 Action 解析。
3. 定义规范化 `ax-ir/0.1`：统一 JSON 排序与表达式树，不携带空白和注释。
4. 为 `always` 不变量和 Action 语义生成模型级验证义务。
5. 建立可达有限状态穷举器，输出具体违反性质/无后继/覆盖冲突轨迹。
6. 构建 SHA-256 内容寻址仓库、SQLite 运行登记与证据有效性再评估。
7. 建立仅模型级 Gate；真实 C++ 目标缺少绑定和实现级证据时必须阻断。
8. 用故障样例与测试集回归，并留下可复现 CLI。

## C. 可信性与形式化边界

- 状态域中的整数按数学整数解释；不会把抽象无限精度算术直接等价到 C++ int。
- 模型通过时只能支持 P0 可达有限模型与其同步动作边界；不隐含活性保证或 C++ 精化。
- 当穷举资源不足、工具超时、工具摘要或模型摘要变化时，对旧证据不能作当前合格证据使用。
- 历史 Outcome 不改写，通过新建 FreshnessAssessment 表示其对当前版本是否适用。
- 允许结果 `Approved(target=model)` 仅意味着抽象模型的 P0 Gate 满足，不代表真实系统可以发布。

## D. 工程上的限制及策略

- `.ax` 文法中目前每个模型至少有一个动作和一个 `always` 性质，只允许同步请求—结果事件。
- 目前未产生源码级 SourceMap，诊断以错误类别和语义 ID 为主，精确行列号可在下一轮完善。
- 验证器和 SQLite 在本地同一用户权限下运行，不构成生产级安全边界；AI 隔离、签名授权与审计归属未实现。
- P0 数据库保存的是可追溯运行与工件引用，但尚未提供对象存储 GC、跨主机复制及恢复功能。
- 引入任何新语义扩展都必须维持 AX-B01—AX-B09；当前 `ax-sem/0.1` 只代表已实现的语义子集。

## E. 进入 P1 的门槛

- `pytest -q` 全部通过，正确和故障模型结果可重复。
- 正确模型生成一致 Canonical IR 摘要。
- 不正确模型产生可复现的状态/输入/结果轨迹。
- 给定只有模型级证据的候选，C++ Gate 始终 Blocked。
- 改变语义摘要或检查工具指纹使旧证据不再 Current。
- P1 启动前补充正式的 C++ Binder 接口、构建沙箱设计和强制质量准入策略。
