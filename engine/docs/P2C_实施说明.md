# Axiom P2c 第三批设计与实现记录（工程版本 0.5.0）

## 实现目标与冻结边界

依据 AX-B01—AX-B09、概要设计 V1.0 实施；行为语义基础、验证证据等级与 C++ 安全边界不改变。本阶段弥补 P2b 仅检查跨模型**声明的证据依赖**、不执行任何跨组件行为检查的问题。

## 新能力

1. `product.py` 实现双模型显式同步乘积验证：两个模型均使用已有 `.ax` 类型/状态/Action/不变量语义；由同步描述确定原子配对步骤，生成可到达的乘积状态空间，执行跨组件状态关系检查及输出相等检查。
2. `product_store.py` 实现模型摘要、规范化同步声明、验证报告、校验工具摘要的内容寻址证据记录；存入 `product_runs`，对声称 `Bounded` 的报告进行独立完整重放。
3. `product-gate` 在**局部 P2 模型证据 + 当前同步乘积证据**全部满足时才提供 `Approved`，明确限定 `finite-abstract-product-integration-check`，不批准 C++ 代码或生产发布。
4. `audit.py` 扩展检查同步乘积报告的对象完整性、索引一致性、工具摘要和有限穷举范围。
5. 新增正确、错误状态和错误输出三类双模型示例及自动化回归测试；保留 P0–P2b 原有 CLI 和用例。

## 同步组合的语义

若组件 A 与 B 的动作由 `sync` 成对绑定，且两个动作输入域相同，组合转移为 `((sA,sB),x) -> ((sA',sB'),(yA,yB))`，其中每个局部转移满足各自的 Action 关系，同时要求 `yA == yB`。两端状态字段形成不相交的命名空间 `A.field`、`B.field`。初始状态是两端初始集合的笛卡尔积。每个同步步骤检查一组声明的关系不变量，包含每个可到达的组合状态。现阶段不允许任何未配对 Action，防止在忽略外部操作的情况下错误宣称已验证。

完整遍历且无反例才为 `Bounded`；任一关系性质或输出条件失败输出 `Violated` 与轨迹；时间、状态数或转换数上限触发 `Unknown`；不支持或不完整语义输入拒绝处理。

## 反例用例

Source 与 Mirror 两个模型，分别保证 `on` 为布尔值，均可独立通过局部有限验证。正常 Mirror 将 `on'` 更新为 `desired`；错误 Mirror 将其更新为 `!desired`。两个局部性质仍然满足，但关系性质 `Source.on == Mirror.on` 在一次共同执行后被打破，验证器返回明确的同步输入、各自输出和后继状态。该实验**不能推导真实 C++ 模块的正确性**。

## 可靠性设计

- 所有 .ax 路径限定在 manifest 目录内；不接受越界路径与最终文件符号链接。
- 只有两个组件、完整且不重复的 Action 配对、精确一致的输入输出域才可验证。
- 使用无可执行字符串的结构化性质 DSL；限制运算符并进行类型检查。
- 原始声明与模型内容以 SHA-256 绑定；旧乘积证据不能用于已变化的同步关系或任意模型。
- 本地存储不是强安全信任根；同权限恶意修改仍需外置签名及隔离验证器解决。
- 未建立 C++ 组合行为与抽象乘积之间的精化关系。

## 后续顺序

P1 安全执行隔离与可信签名仍未完成。之后优先扩展乘积协议为受控交错和多组件组合，再建立具体 C++ 实现/接口到抽象 Action 的可检查绑定；最后进行连续演化和验证耗时对照实验。
