# Axiom P2h / V1.0.0 实施与验收

基线：Axiom 0.2 AX-B01—AX-B09，概要设计 V1.0。P2 第八批研究原型；软件版本 1.0.0。

## 新功能及实现边界

1. `src/axiom/cpp_project.py`：严格多文件清单、实际 GCC 传递依赖扫描（`-M`）、内容寻址缓存键、受限的独立编译和执行、测试目标证据存储、Gate。每个测试都以固定 GCC 参数在 normal 和 UBSan 模式编译；离线内容寻址对象使用现有 Workspace。
2. 源文件清单为显式正向白名单，只接收无路径分隔符、非符号链接的 `.cpp/.hpp`；项目目录新增未登记代码文件直接拒绝，所有项目代码文件必须参与至少一个测试。
3. 每个目标缓存键包括：当前 .ax 语义摘要、目标源码与声明的头文件、GCC 输出的传递依赖文件内容摘要、编译器可执行文件摘要及版本、构建参数、测试输出预言机与工具自身源码摘要。
4. 跨组件集成测试永不复用；每次 Gate 必须重新计算当前依赖键、当前抽象模型的有界检查与所有目标报告条件。
5. 与 Axiom 状态规格建立的是“版本与证据关联”，**并非形式化精化证明**；两种模式的有限运行测试、C++ 程序自检预言机与模型级 `Bounded` 各有各的保证边界。

## 可复现实测

- `PYTHONPATH=src python -m pytest -q tests/test_cpp_project_p2h.py`：5/5 通过（独立运行）。
- `PYTHONPATH=src python scripts/run_p2h_demo.py`：正常项目 3 个目标运行通过；修改 `format.cpp` 后旧 Gate 为 Blocked，新一轮仅重验 format 与 integration，ledger 证据被复用；人为引入错误收据后两个有关目标失败，Gate 为 Blocked。
- 演示实测（单次、环境依赖）：初次全量 10.045 秒，单处源代码变化后的增量 7.229 秒。不应以此声称一般性或统计显著的加速。
- 旧版全套回归检查在本轮环境中出现执行超时，**不能宣称全量 156/156 通过**。之前批次的已记录结果不代替本次实际回归；P2h 作为受限专项验收，不进入生产或完整 P2 退出验收。

## 剩余风险与限制

1. 尚无证明 C++ 实现与 Axiom 行为模型精化关系的工具；C++ 测试预言机需要独立审查。
2. 真实构建和运行仅支持该实验受限平面源码结构和单 GCC 工具链。可执行文件运行时动态库、非 /usr 系统资源与外部服务并不由缓存键完整追踪。任何平台变化需重新验证。
3. Linux namespace/chroot 是实验性隔离，尚无完整 seccomp/cgroup 强制隔离与安全审计；不能执行不可信生成的恶意代码。
4. 实现级证据仅保存在本地 SQLite + 内容寻址对象，不具备独立信任根、受保护的构建者身份或完整的软件供应链签名。
5. 两个组件/三个测试规模不具有现实大型项目代表性；验证加速需要更大规模、控制变量和多次重复统计。
6. 版本恢复至与原始源码完全相同的内容时，允许恢复精确键对应的缓存证据；不是对代码的语义相似性推断。
