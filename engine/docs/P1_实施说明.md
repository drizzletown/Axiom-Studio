# Axiom P0 + P1 · 行为模型与真实 C++ 候选的受控验证原型

**冻结理论基线** AX-BL-0.2（AX-B01—AX-B09）；**概要设计** AX-HLD-1.0；**当前工程版本** axiom-prototype 0.2.0。

> **P1 是受限的 C++ 测试级原型，不是通用 C++ 形式化验证器，不是生产级代码执行沙箱，不授予生产发布许可。**

## 1. 已完成的实际链路

`有限 .ax 规格 → 规范化 Semantic IR → 模型有限穷举 → 显式 C++ 绑定 → 真实 g++ 编译 → 正常/ASan+UBSan 执行 → 有限差分与边界检查 → 工件内容摘要与证据存储 → C++ 测试级 Gate`

- P0 源码完整保留，`ax check|plan|verify|gate|impact|evidence` 仍可使用。
- P1 新增 `ax cpp-verify` 与 `ax cpp-gate`；历史 `ax gate --target cpp` 仍是 P0 的严格阻断接口，新 C++ 测试级准入通过 `cpp-gate` 单独检查。
- 支持双账户 `TwoAccount` 的 `move(m)`：状态 `a,b` 与输入 `m` 均为有限整数，输出 Bool。使用显式 JSON `RefinementLink` 子集，禁止静默推导不支持的映射。
- 固定纯同步 ABI：候选实现 `AxMove axiom_move(int64_t a,int64_t b,int64_t m)`；`AxMove` 具有 `a,b,success` 三个成员。受信任运行器为每个可达状态与输入生成请求，捕获正常执行及 ASan/UBSan 结果。
- 本模型共 **4 个可达状态 × 4 个输入 = 16 个状态/输入对**。在每种二进制模式中顺序及逆序各重放一遍，共每个模式 32 次观察（两种构建模式共 64 次）。核对每个具体结果是否属于抽象 Action 允许的后继集合。
- 保存源码、绑定、生成的 C++ harness、编译器配置、正常与 Sanitizer 二进制的 SHA-256 工件；Gate 根据目标版本实时检查匹配关系及工件内容完整性。
- 候选源码、绑定、编译器/选项或规格变化时，不能继承旧运行证据；模型验证证据独立存在，不能代替具体实现证据。

## 2. 环境与运行

- Python >= 3.10；Lark >= 1.1；pytest >= 7；GCC/G++（本次实测 14.2.0）支持 C++20、AddressSanitizer 与 UndefinedBehaviorSanitizer。
- **仅对可信示例候选执行。** 当前只提供子进程 timeout 与 CPU/core 限额，无进程级权限隔离、网络封禁或文件系统沙箱。不得运行来自不可信源的任意代码。

```bash
python -m pip install -e '.[test]'
pytest -q
bash scripts/run_p1_demo.sh
```

或逐步操作（新工作区）：

```bash
ax --workspace .axiom-p1 verify examples/two_account.ax
ax --workspace .axiom-p1 cpp-verify examples/two_account.ax \
    --candidate cpp/correct.cpp --binding cpp/binding.json
ax --workspace .axiom-p1 cpp-gate examples/two_account.ax \
    --candidate cpp/correct.cpp --binding cpp/binding.json
```

`cpp-verify` 退出码 0=Tested、2=Violated、3=Unknown，无法解析/不支持/IO 错误为 1；`cpp-gate` 阻断返回 4。

## 3. 受控缺陷样例

| 示例 | 缺陷 | 预期结果 |
|---|---|---|
| `correct.cpp` | 正确状态更新 | Tested，满足测试级 Gate |
| `broken_mapping.cpp` | 转入余额未变 | Violated（差分不一致） |
| `broken_boundary.cpp` | `m<a` 排除了合法边界 | Violated（差分不一致） |
| `broken_frozen_input.cpp` | 隐藏跨调用状态 | Violated（重复测试） |
| `broken_overflow.cpp` | 特意制造 `int32_t` 有符号溢出 | Violated（UBSan） |
| `broken_compile.cpp` | 故意无法编译 | Unknown（构建失败），不满足 Gate |

## 4. 保证边界与未解决问题

1. 模型级 `Bounded` 仅针对 `ax-sem/0.1` 有限状态穷举。
2. 实现级 `Tested` 仅说明本次运行观察中，指定二进制/序列的行为满足抽象有限模型，并通过所执行的 Sanitizer 检测；**不能等价于任意调用序列上的程序正确性，更不能视为精化定理**。
3. 本期不支持持久化、线程交错、网络、异常调度、多模型连接、隐式系统调用效果或任意 C++ 对象状态抽象。
4. 源文件限单一受控翻译单元（不允许候选显式引用本地引号头文件）；工具链环境摘要虽包含编译器可执行文件、版本、目标和参数，但尚未涵盖完整系统库/内核运行环境的供应链来源证明。
5. 受信任 harness 与本地 SQLite/工件目录仍在同一用户权限下；用户可修改数据库或直接调用内部 API，故**此处不存在抵抗恶意 Agent 的独立信任边界**。
6. Gate 的 `Approved` 目标仅为 `cpp-tested-prototype`，不代表生产发行批准，也不证明全域内存安全。
7. P2 将研究类型化依赖及证据安全复用；P3 扩展并发幂等；真正的进程隔离、授权与可审计签名是后续正式化的安全先决条件。

## 5. 目录

- `src/axiom/cpp.py`：绑定、有限关系 oracle、真实编译、正常/ASan+UBSan 执行与差分比较。
- `src/axiom/store.py`：历史 P0 Evidence/Gate + P1 候选证据与严格摘要匹配。
- `cpp/`：受控 C++ 候选和 `binding.json`。
- `scripts/run_p1_demo.sh`：隔离工作区中的 P1 可复现演示。
- `tests/`：P0 + P1 自动化测试。
- `docs/`、`reports/`：实施与验收资料。
