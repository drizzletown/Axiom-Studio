# Axiom P2d 第四批：工程实施与验收（0.6.0）

## 目标与变更边界
遵循 Axiom 0.2 理论冻结基线以及《概要设计 V1.0》。保留既有 P0/P1/P2a/P2b/P2c 代码；新增类型化 manifest 对双组件原子动作进行强制全覆盖分派（`sync` 或 `independent`），用 BFS 穷举全部可达全局状态；增加本地证据重放和有条件离线签名。

## 功能范围
- `ax-interleaving-composition/0.1`：恰好两个模型；显式、原子同步 pairs 共享输入并要求输出相等；独立 Action 可任意交错；每次原子转换后立即检查跨组件性质。
- `ax interleave-verify`：`Bounded` 仅在有限可达状态完全穷举结束后产生；发现违反返回 `Violated` 与逐步轨迹；资源限制、超时统一 `Unknown`。
- `ax interleave-gate`：双组件局部模型有当前有效的验证记录、组合有匹配的 `Bounded` 记录，才能作出原型模型级 `Approved`。
- `ax audit`：检查新增证据表与内容寻址对象的结构、版本、哈希与结果关联。
- 离线签名：受控外部签名者持有 Ed25519 私钥，在独立重放局部与组合模型检查及审计后签发指定证据摘要；验收端必须使用固定公钥重算并验证。

## 验证结果（在本次环境执行）
- 原有基线 96 个测试；新增 25 个测试，合并回归 121/121 通过。
- 正确组合：可达 2 个全局状态，检查 48 个有限枚举后继候选，`Bounded`。
- 错误组合：两组件各自验证通过，但 `Mirror.set(desired=true)` 单边独立修改后违反 `Source.on == Mirror.on`，返回长度 2 的反例（含初始状态）。
- Gate 在缺少局部证据时阻断；局部证据补齐且组合证据匹配后模型级批准。
- 非法分派/未知引用/越界路径/输入或输出不匹配/状态预算不足/证据伪造/代码漂移均被阻断或返回 Unknown。
- 独立签名测试覆盖正确公钥、错误公钥、签名篡改、过期 manifest、错误 signer、工作区私钥位置和拒绝未获 Gate 的签名。

## 关键限制与未完成事项
本轮仅支持双组件、原子转换与有限状态、安全性质。没有细粒度共享内存交错、消息队列、网络分区、公平性或活性检查；没有实现真实 C++ 与抽象组合模型间的精化证明，也没有实现不可信 C++ 的安全沙箱。签名依赖**独立受保护的签名者和预先可信公钥**；相同权限域内保留签名私钥不具有可信防篡改能力。

## 后续 P2/P3 准入条件
1. 引入受审计 OS 沙箱，并从受信任服务调用 C++ 编译、执行与测试；否则禁止不可信代码。
2. 实现受限的实现到抽象事件映射，并通过真实并发 C++ 轨迹验证观察行为（首先应明确是测试而非一般形式化精化证明）。
3. 建立多轮真实代码变更的语义依赖传播与成本对照实验；统计漏检、误报、失败原因与运行成本。
